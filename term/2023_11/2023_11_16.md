  - モジュール 1 ：AWS の概要、グローバルインフラストラクチャとコンピューティング
    - マルチAZ
      - 複数のアベイラビリティゾーンを持つ
    - Amazon EC2 (Amazon Elastic Compute Cloud)
      - インスタンスとはサーバーのこと
      - 立ち上げ時の設定
        - キーペア
          - インスタンスへの接続のために使用する、鍵
        - 高度な詳細
          - ユーザーデータ
            bash コマンド等を入力することができる。
      - 立ち上げ後のインスタンスの状態
    - クラウドのサービスは大きく２つに分かれている
      - アンマネージドサービス、マネージドサービス
      - EC2はアンマネージド
      - サーバーレスコンピューティング（マネージドサービス）
        - プロビジョニングをお任せできる
        - スケーリングを自動で行う
        - 実行した時間だけ課金
        - AWS Lambda
          - フルマネージド型のコンピューティングシステム
          - ランタイム（プログラムの実行環境）
            - pythonやrubyを選ぶことができる
          - GASに似ている。
          - 設定- 設定URL でURLを選ぶことができる。
          - プログラムのことだけ考えれば良い。
  - モジュール 2 ：ストレージとデータベース
    - ストレージ
      - データを保存しておく場所のこと
      - オブジェクトストレージ(共有ストレージ)
        - Amazon S3(Amazon Simple Storage Service)
          - サーバーレス
          - 容量管理はお任せ、オブジェクト数は無制限
          - 耐久性 99.999999999%(イレブン9)の耐久性
          - イベントトリガーとしてLambda関数を呼び出せる
          - リージョンの中で管理をする
          - バケットを作成
            - バケット名は唯一無二(各オブジェクトごとにバケット名を付与したアクセスURLを作成するため。)
            - ブロックパブリックアドレス
              - デフォルトはパブリックアクセス拒否
            - オブジェクトアクション
              - 署名付きURLで「xxx」を共有
                - 時間を決めて、パブリックアクセスができるようになるリンクを作成。
                - 時限アクセスが可能
        - 長期間の保管に向けて
        - S3 Glacier
          - コールドデータを置く場所。
          - 低コスト
          - 取り出しに時間とお金がかかる。
          - 磁気テープの代用として使える。
      - ブロックストレージ
        - Amazon Elastic Block Store(Amazon EBS)
          - 処理速度を高速化したいデータの保存に適している
          - ブロックストレージでは、データを「ブロック」という固定された長さの単位に分割して管理します。このブロックには番号が割り振られているため、特定のデータを書き換えたい場合はその番号をもとに検索することが可能です。これによりデータへのアクセスが容易になり、処理速度が上がります。
    - データベース
      - リレーショナルと非リレーショナル
      - リレーショナルデータベースについて
        - AmazonRDS (Amazon Relational Database Service)
          - 運用負荷の軽減
          - * 二つ以上でやりことがほとんど 冗長構成
          - フェイルオーバー
          - マルチAZはボタンひとつ
        - Amazon Aurora
          - 高い可溶性と耐久性
          - 互換性
      - 非リレーショナルデータベース(NoSQL)
        - KVS
        - Amazon DynamoDB 
          - フルマネージドサーバー
  - モジュール 3 ：ネットワークとセキュリティ
    - Amazon Virtual Private Cloud (Amazon VPC)
    - サブネット分割
      - サブネット（セグメント）
        - パブリックサブネット
        - プライベートサブネット
    - ハンズオン
      - VPCはリージョンごとに設置
      - 「VPCのみ」「VPCなど」
        - VPCなどの場合は、AZやサブネットを作成できる
          - サブネット、ルートテーブル、インターネットゲートウェイ
    - インフラストラクチャの保護
      - セキュリティグループ
        - 縦深防御

          - サブネット単位で設定
        - ルートテーブル
      - インフラストラクチャとの接続
    - セキュリティ
      - AWSの責任共有モデル
      - 認証、認可
        - IAM(AWS Identity and Access Management)
          - 認証認可管理
          - IAM ポリシー
            - できる、できない両方記載すると、できないが優先される。
            - IAM ユーザー
            - IAM グループ
            - IAM ロール
              - EC2からS3にアクセスする際の認証認可を付与することができる
              - ちなみに、アクセス時のアクセスキーや秘密鍵を書いておくのはNG
          - リソースベースのアクセス制御
      - アクセス状況の追跡
        - Cloud Trail
          - 監査証跡を取ってくれる
            - 誰が
            - 何を
            - いつ
            - どこへ
        - ログファイルはS3バケットへ保存される
        - ベストプラクティスの確認
          - AWS Trusted Advisor
            - コスト削減
            - パフォーマンスの向上
            - セキュリティの強化
